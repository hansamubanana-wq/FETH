# Codex実装指示書: グラフィック品質ティア（能力判定＋双方向調整＋設定UI）v0.17.0

## 背景（現状の3つの実害）

現在 `src/race3d.js` は「FPS実測 → 3秒平均が30fps未満なら品質を落とす」方式（`_applyQualityFallback`）。
端末カテゴリ判定（旧 `isMobile`）を廃した方向性は正しいが、以下の穴がある。

1. **片道切符**: `qualityLevel` は上がるだけで下がらない。バックグラウンド復帰や他アプリの
   一時的な負荷で一度落ちると、高性能端末でも以後ずっと低品質のまま
2. **後追いで最初がカクつく**: 判定に3秒×最大3段。レースは約30秒なので体験の序盤が調整中になる
3. **メモリ律速に対処できない**: 直近のテクスチャ導入でボトルネックが「描画速度」から
   「VRAM」へ広がった。1024²テクスチャは約4MB＋ミップマップ、2048×1024パノラマは約10MB。
   **メモリ不足は解像度や影を削っても解決しない**（クラッシュ/強制リロードになる）

## 実装する3層構成

### 層1: 起動時の能力プロファイリング（開始ティアを決める）

初回レース開始前に軽量な判定を行い、**最初から妥当なティアで始める**（序盤のカクつきを消す）。
判定材料の例（取得できないものは無視してよい。1つに依存しないこと）:

- `window.devicePixelRatio`
- `navigator.deviceMemory`（端末RAM目安・未対応ブラウザあり）
- `navigator.hardwareConcurrency`
- WebGL: `MAX_TEXTURE_SIZE`、`WEBGL_debug_renderer_info` のGPU名（取得可なら）
- 画面の実ピクセル数（DPR × CSSサイズ）＝実際の塗り面積

これらから `low` / `mid` / `high` の開始ティアを決める。**GPU名の文字列マッチに強く依存しないこと**
（将来の端末で誤判定するため、あくまで補助）。判定不能なら `mid` から始める。

### 層2: 実行中の動的調整を双方向にする

- 現在の「30fps未満で1段下げる」を維持
- **加えて、余裕があれば1段戻す**。往復振動を防ぐためヒステリシスを入れること:
  - 下げる: 3秒平均 < 30fps
  - 戻す: 3秒平均 > 45fps が **連続2回以上（＝約6秒）継続**したとき
  - 同一レース中に同じ段を往復した場合は、その段より上へは戻さない（発振防止のラッチ）
- バックグラウンド復帰直後の長いフレーム間隔を性能とみなさない既存ガードは維持

### 層3: 設定UIで手動上書き（自動／低／中／高）

- ホーム画面（または設定パネル）に「グラフィック品質: 自動 / 低 / 中 / 高」を追加。
  **デフォルトは「自動」**
- 選択を `localStorage` に保存し、次回起動時も維持
- 手動選択時は層1・層2の自動制御を**無効化**（ユーザーの意思を尊重）。
  ただし「自動」に戻せば再び自動制御に復帰する
- UIは既存のダーク×ゴールドのテーマに合わせ、既存のホーム画面レイアウトを崩さないこと

## ティアごとの設定内容

| 項目 | low | mid | high |
|---|---|---|---|
| pixelRatio 上限 | 1.0 | 1.5 | 2.0 |
| 影 | 無効 | 有効・1024² | 有効・2048² |
| テクスチャ解像度 | 512px系 | 1024px系 | 1024px系（パノラマは最大） |
| パーティクル(砂埃/紙吹雪/フラッシュ) | 半減 | 標準 | 標準 |
| 観客数・星の数 | 減 | 標準 | 標準 |

- **テクスチャ解像度をティア対象に含めるのが今回の要点**（メモリ律速への唯一の対処）。
  低ティア用に 512px 版を用意すること。前ラウンドで生成したテクスチャの縮小版を
  `assets/art/tex/512/` などに置く（image 2.0での再生成でも、縮小でもよい）
- 低ティアでは空のパノラマを使わず、既存のグラデーション空にフォールバックしてよい

## 制約（毎回同じ・必読）

- ビルドなし静的サイト維持、Vanilla JS + three.js (importmap)
- **動的カメラの「全馬が常に画面内」ロジックには手を入れない**
- **レースバランス（着差・勝率分布）とレース所要時間は変えない**
- 2Dフォールバック（src/race.js）を壊さない
- オンライン対戦のシード同期を壊さない（品質はローカル設定なので同期不要。
  ただし品質差で**レース結果や進行がズレないこと**を必ず確認）
- 完了時 `src/version.js` を APP_VERSION 0.17.0 / APP_BUILD 22 に、index.htmlのバッジも更新
- タスクごとに日本語メッセージで独立コミット。push・デプロイはしない

6. **双方向調整の動作確認**: 意図的に低FPS状態を作って段が下がり、負荷を戻すと
   段が復帰することを（ヒステリシス通りに）確認して報告
